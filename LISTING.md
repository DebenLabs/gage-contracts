# List a token

How gage handles a request to accept a token as collateral, or to add a pool or exit route for a token it already accepts. **A request is not a promise:** gage lists only what passes its published criteria, and decides each request on its own.

1. **Open an issue** with the [List a token](../../issues/new?template=token-listing.yml) form.
2. **Screening.** gage screens the token, and the pool or route a sale exits through, against its published criteria: [Collateral rules](https://docs.gage.cash/protocol/collateral-rules). It answers in the issue.
3. **Listing batch.** A token that passes goes into gage's next Safe listing batch.
4. **Closed with the transaction.** The issue is closed with the transaction that listed the token, or with the reason it was not listed.

The tokens accepted today: [Accepted collateral](https://docs.gage.cash/borrow/accepted-collateral). Partners already in direct talks with gage don't need an issue.
